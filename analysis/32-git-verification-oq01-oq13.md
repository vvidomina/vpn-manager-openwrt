## 4. `git diff --check` — точная область действия

```text
git diff --check
exit 0
```

**Что именно проверяет команда:**

1. Только **отслеживаемые** изменения (рабочая копия против индекса). Untracked-файлы (`29`–`32`, патчи) **не проверяются**.
2. Только **пробельные** дефекты: пробелы в конце строки, пробел перед табуляцией в отступе, пустые строки в конце файла, «битые» строки, которые Git считает таковыми при применении.
3. **Не проверяет**: конфликтные маркеры, синтаксис и рендеринг Markdown, битые ссылки, кодировку, смысловые противоречия, соответствие требованиям и решениям владельца.

Предупреждения Git о `LF will be replaced by CRLF` относятся к рабочим файлам с CRLF и ошибкой не являются; на exit code они не влияют.

**Вывод: exit 0 означает отсутствие пробельных ошибок в отслеживаемом diff, и ничего больше.** Подтверждением корректности документации он не является.

## 5. Конфликтные маркеры и кодировка — отдельные проверки

```text
grep -rnE '^(<<<<<<<|=======|>>>>>>>)' analysis/*.md      → совпадений нет
grep -rl $'\uFFFD' analysis/*.md                          → совпадений нет
```

Маркеры искались в начале строки, как их создаёт Git при конфликте; разделители таблиц `|---|---|` под шаблон не попадают. Проверены и untracked-документы №29–№32.

**Переводы строк.** Для каждого `analysis/*.md` число строк, содержащих `\r`, сравнивалось с `wc -l`: расхождений нет (файлы в рабочей копии — CRLF, как и до U7). Проверка подтверждает только целостность переводов строк; содержимое она не проверяет.

## 6. Untracked-документы: сверка по контрольным суммам

Полнота включения untracked-документов в патч проверена **сравнением SHA-256 исходного файла и содержимого, извлечённого из патча** (все строки соответствующей секции с ведущим `+`), а не совпадением количества строк.

| Файл | Байт | SHA-256 исходника = SHA-256 из патча |
|---|---|---|
| `analysis/29-oq09-source-review.md` | 39 188 | **да** |
| `analysis/30-oq09-decision-integration.md` | 28 902 | **да** |
| `analysis/31-oq01-oq13-decision-integration.md` | 34 634 | **да** |
| `analysis/32-git-verification-oq01-oq13.md` | — | **в патч не входит** (мета-отчёт, §3 п. 3) |

Команда сверки (для каждого файла):

```bash
git diff --no-index -- /dev/null analysis/<файл> >> corrective-review-u7.patch   # при генерации
awk '/^diff --git /{insec=($0 ~ "b/analysis/<файл>$"); next}
     insec && /^\+\+\+ /{next} insec && /^\+/{print substr($0,2); next}' \
     corrective-review-u7.patch | sha256sum                                       # при проверке
sha256sum analysis/<файл>                                                        # эталон
```

Дополнительно выполнена обратная проверка применимости ко всему патчу:

```text
git apply --check -R --whitespace=nowarn corrective-review-u7.patch
exit 0
```

Обратное применение проходит без конфликтов, то есть содержимое патча **точно соответствует** текущей рабочей копии (патч не «отстал» от файлов). Прямое применение к рабочей копии не выполнялось: изменения уже в ней. Применение к чистой копии `aee3eec` в отдельном каталоге не выполнялось (создание worktree/копии в этой задаче не предусматривалось) — это ограничение проверки, а не подтверждённый дефект.

## 10. Область действия каждой машинной проверки (без расширения)

| Проверка | Что подтверждает | Чего **не** подтверждает |
|---|---|---|
| `git status` / `git rev-parse` | ветку, HEAD, пустой индекс, наличие изменений и untracked | содержательной корректности |
| `git diff --stat` / `--numstat` | объём и распределение изменений по отслеживаемым файлам | что изменения полны по смыслу |
| `git diff --check` | отсутствие пробельных ошибок в отслеживаемом diff | untracked, Markdown, ссылки, кодировку, смысл |
| `grep` конфликтных маркеров | отсутствие маркеров в начале строки в `analysis/*.md` | отсутствие иных дефектов слияния |
| `grep -rl $'\uFFFD'` | отсутствие символа замены в `analysis/*.md` | корректность кодировки во всех инструментах/рендерерах |
| сравнение `\r`-строк с `wc -l` | сохранение CRLF в каждом файле | содержимое строк |
| SHA-256 исходника и извлечённого из патча текста | **идентичность содержимого** untracked-документов | идентичность отслеживаемых секций (для них проверка — обратное применение) |
| `git apply --check -R` | соответствие патча текущей рабочей копии | применимость к чистой копии HEAD |
| подсчёт определений REQ и висячих ссылок | наличие ID и отсутствие «живых» висячих ссылок | смысловое соответствие требований решениям |
| `git apply --stat` | разбор патча без ошибок и его сводку | успешное применение и работоспособность результата |

Ни одна из этих проверок не заменяет семантическое ревью и не доказывает согласованность документов.

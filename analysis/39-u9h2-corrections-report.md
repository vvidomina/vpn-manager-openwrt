## 5. Уточнение модели gRPC startup failure

Подтверждено исходниками тега v26.9.9:

- `app/commander/commander.go`: при непустом `listen` ошибка `net.ResolveTCPAddr` или `internet.ListenSystem` возвращается из `Start`;
- `core/xray.go`: `Instance.Start` возвращает ошибку на первой неудаче feature и не продолжает запуск.

Отсюда модель трёх ситуаций:

- **A. Ошибка создания listener при старте.** Xray не запускается. Приложение фиксирует отказ запуска движка: `DEGRADED/ENGINE_DOWN` и откат на last-good по инвариантам №20 §8.1. Это не `api_error`.
- **B. Listener работает, `ObservatoryService` отсутствует** (опечатка в `api.services`). Xray работает; `GetOutboundStatus` возвращает `Unimplemented`; публикуется `observability=error` с `error_code=unimplemented`; отказ движка не объявляется.
- **C. Ошибка вызова RPC при работающем Xray** (таймаут, `DeadlineExceeded`). Публикуется `observability=error`; состояние процесса берётся из S2.

`connection refused` не классифицируется по тексту ошибки: сначала проверяется, запущен ли процесс; при остановленном процессе это `ENGINE_DOWN`.

## 6. `Unimplemented`, `api_error`, `ENGINE_DOWN`

| Состояние | Условие | Что публикуется | Что запрещено |
|---|---|---|---|
| `Unimplemented` | сервис не зарегистрирован (опечатка, пустой список) | `observability=error`, `error_code=unimplemented` | объявлять отказ Xray или VPN |
| `api_error` | ошибка вызова API при работающем Xray | `observability=error`, отдельное поле | подставлять `no_data`, `healthy`, `unavailable` |
| `ENGINE_DOWN` | процесс не запущен, отказ запуска, ошибка bind | состояние движка и причина | выдавать за ошибку наблюдаемости |

Сценарии 123 и 124 переписаны так, чтобы различать эти три состояния достижимыми действиями: пустой список, опечатка сервиса, остановленный Xray.

## 8. Формула свежести Observatory

Свежесть считается по `last_try_time`, а не по `last_seen_time`:

```text
fresh  ⇔  now − last_try_time ≤ TTL
TTL    =  T_cycle + grace
T_cycle = probeInterval + max_probe_time                      (enableConcurrency: true)
T_cycle = N × (probeInterval + max_probe_time)                (enableConcurrency: false)
```

- `N` — число outbound в `subjectSelector`;
- `max_probe_time` — таймаут одной пробы (HTTP 5 с, TLS-handshake 5 с; №18 §7.2.1);
- `probeInterval` берётся из конфигурации;
- `grace` — параметр реализации `[Т]`, численное значение не утверждено и требует измерения на целевой сборке;
- `last_try_time = 0` относится к `no_data`, а не к `stale`.

Формула не подменяет измерение и не назначает `grace` без данных.

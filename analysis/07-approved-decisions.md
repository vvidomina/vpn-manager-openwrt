## 1. Что изменилось по существу

| Решение | Было в документах №1–№4 | Стало после утверждения |
|---|---|---|
| D-01 IPv6 | «Политика IPv6 не определена»; рекомендация — отключить IPv6 для клиентов; риск расширения объёма на 30–50 % | v1 — **IPv4-only** по внешней маршрутизации; IPv6-подсистему не отключать; глобальный IPv6 на WAN обнаруживать, предупреждать, клиентский выход безопасно ограничивать. Полная поддержка IPv6 в v1 не делается. **Уточнение 22.11.2026:** у провайдера IPv6 нет (подтверждено обследованием); IPv6 нужен только для внутренних нужд роутера; IPv6-туннелирование и IPv6 TProxy не реализуются; незаметный внешний IPv6-выход клиентов запрещён; механизм ограничения — P-01 |
| D-02 Мониторинг | Интервал/timeout не заданы; 30 с / 8 с — только рекомендация | 30 с / 8 с / ≤3 параллельных / 2 независимых fail — **утверждённая стартовая спецификация**, подлежит измерению |
| D-03 Ручной выбор | Неясно, применяется ли 3 × 5 мин к ручному выбору | Ручной выбор — немедленно, без гистерезиса; автовозврат — только 3 успеха × 5 мин; неудачный выбор не ломает текущее подключение |
| D-04 Протоколы | «Импорт VMess/Trojan» без ясности, работает ли | VMess и Trojan — **полноценно работают** в v1 |
| D-05 Транспорт UI | Выбор между ubus и HTTP не сделан | **ubus/rpcd + ACL**, сетевой порт демона не открывается |
| D-06 Staged apply | Механизм не выбран; trial-окно «десятки секунд» как идея | Обязательная последовательность: подготовка → `xray -test` → preflight outbound → проверка nft → применение → trial с проверкой трафика → commit/rollback; canary — опция; длительность измеряется |
| D-07 Restricted JSON | Определение не задано | Явный признак провайдера → иначе ручной выбор типа; эвристики запрещены |
| D-08 Сторонние стеки | Рекомендация «детект + управляемая очистка» | Утверждено: pre-flight только обнаруживает; очистка — отдельное действие с подтверждением и бэкапом; автоудаление запрещено |
| D-09 Flash-журналы | Объём не задан | RAM — подробно; Flash — только failover/emergency/apply-rollback/критические ошибки, кольцо 256 КБ + 1 ротация, rate limit |
| D-10 Backup | Состав не перечислен | Состав утверждён (подписки с токенами, серверы, профили, назначения, устройства, DNS/UDP, маршрутизация, версия схемы); Geo/логи/время исключены; без шифрования, права, предупреждение |
| D-11 Conntrack | «Диагностический показатель» как рекомендация | Утверждено: не критерий отказа, не влияет на failover, предупреждение > 80 %, sysctl не менять автоматически |
| D-12 Flowtable | «Проверить, при необходимости отключать» | Утверждено: не отключать глобально; сначала точечное исключение трафика; глобальное отключение — только с измерениями и отдельным согласованием |
| D-13 Подписки | Доопределение в узком месте | Утверждён полный порядок: приоритет подписок → сервер → профиль (кроме Restricted) → Pending reconnect; предпочтения не стираются |

**Важно:** рекомендация редакции 1 по Q-01 (отключить IPv6 для LAN-клиентов) **не принята**. Утверждён другой вариант: не отключать подсистему, а обнаруживать глобальный IPv6 и безопасно ограничивать клиентский выход. Документы №1 и №3 обновлены, чтобы не содержать прежней рекомендации как действующей.

**Уточнение D-01 от 22.11.2026** (после разрешения на этап 1) внесено в [`05-open-questions.md`](05-open-questions.md) как часть D-01, а не как новое решение. Оно не меняет утверждённую логику, а фиксирует факты и границы:

- у провайдера IPv6-доступа нет (подтверждено: `wan6 up=false`, нет адреса/префикса/default route, `ip -6 route get` → unreachable);
- IPv6-подсистема сохраняется только для внутренних нужд роутера;
- IPv6-туннелирование через Xray и IPv6 TProxy в v1 не реализуются;
- клиент не должен получать незаметный внешний IPv6-выход;
- внутренние IPv6-адреса роутера и клиентов не являются доказательством IPv6-доступа у провайдера;
- механизм ограничения внешнего IPv6 (P-01) остаётся **открытым** и не выбирается до отдельного согласования.

**Уточнение от 22.11.2026 (этап 2).** Xray на устройстве был остановлен владельцем **вручную** для восстановления прямого доступа в интернет — это штатное намеренное действие, а не отказ. Отсюда добавлено решение **D-14** (см. §7): состояние «VPN выключен пользователем» — отдельное штатное состояние; состояние VPN определяется по совокупности шести признаков. Формулировки о «неизвестной причине остановки/аварии» из документов №0–№8 удалены или исправлены; подтверждённым остаётся только недостаток механизма состояния (A-07, S1-03/S1-04).

Прежнее утверждение документов «IPv6 работает, есть IPv6 default route» **опровергнуто обследованием** (документ №8 §1.4, §2). Класс дефекта B-08 сохраняется как архитектурный (IPv6 вне политики), но активной утечки сегодня нет — есть латентный риск S1-01.

# Документ №7. Утверждённые решения: влияние на анализ, риски и план

Дата: 22.11.2026
Основание: «Документ №5. Решения Q-01–Q-13 и технические проверки» (ред. 22.11.2026); краткая фиксация решений.
Нормативный текст решений — [`05-open-questions.md`](05-open-questions.md) (редакция 2). Этот документ фиксирует **что изменилось** в выводах документов №1–№4 после утверждения решений, чтобы не осталось противоречащих им утверждений.

Статус: анализ обновлён; **кодирование не начиналось** и требует отдельного разрешения.

**Редакция 23.11.2026 (третье ревью).** Документ приведён в соответствие с границей IPv6 из ТЗ v1.0 §5. Утверждения о необходимости обнаруживать глобальный IPv6, предупреждать о нём и ограничивать клиентский выход помечены как **исторические и заменённые более новым решением**. В v1: только IPv4 для пользовательского VPN-трафика; нет IPv6 Guard; нет обнаружения глобального IPv6; нет IPv6-фильтров и специальных правил; нет IPv6-тестов; настройки IPv6 OpenWrt не изменяются; риск IPv6 bypass принят пользователем. P-01 — **«закрыт — вне v1»**.

## 1. Что изменилось по существу

| Решение | Было в документах №1–№4 | Стало после утверждения |
|---|---|---|
| D-01 IPv6 | «Политика IPv6 не определена»; рекомендация — отключить IPv6 для клиентов; риск расширения объёма на 30–50 % | v1 — **IPv4-only** по внешней маршрутизации; IPv4-политики не применяются к IPv6-адресам; IPv6-подсистему не отключать. **Не действует — заменено более новым решением (ТЗ §5):** обнаружение глобального IPv6 на WAN, предупреждение о нём и ограничение клиентского выхода (IPv6 Guard). В v1 нет ни Guard, ни детекта, ни IPv6-фильтров и специальных правил, ни IPv6-тестов; настройки IPv6 OpenWrt не изменяются; риск IPv6 bypass принят пользователем (R3-01). **Действует:** IPv4-only для пользовательского VPN-трафика; IPv6-подсистема не отключается; IPv6-туннелирование и IPv6 TProxy не реализуются; внутренние адреса не доказывают наличие доступа. P-01 — «закрыт — вне v1» |
| D-02 Мониторинг | Интервал/timeout не заданы; 30 с / 8 с — только рекомендация | 30 с / 8 с / ≤3 параллельных — **утверждённая стартовая спецификация**, подлежит измерению; **2 последовательных отказа → `DEGRADED`, 3 → недоступность и переключение** (C3-15, вариант Б, 24.11.2026) |
| D-03 Ручной выбор | Неясно, применяется ли 3 × 5 мин к ручному выбору | Ручной выбор — немедленно, без гистерезиса; автовозврат — только три последовательные успешные проверки с интервалом 5 мин; неудачный выбор не ломает текущее подключение |
| D-04 Протоколы | «Импорт VMess/Trojan» без ясности, работает ли | VMess и Trojan — **полноценно работают** в v1 |
| D-05 Транспорт UI | Выбор между ubus и HTTP не сделан | **ubus/rpcd + ACL**, сетевой порт демона не открывается |
| D-06 Staged apply | Механизм не выбран; trial-окно «десятки секунд» как идея | Обязательная последовательность: подготовка → `xray -test` → preflight outbound → проверка nft → применение → trial с проверкой трафика → commit/rollback; canary — опция; длительность измеряется |
| D-07 Restricted JSON | Определение не задано | Явный признак провайдера → иначе ручной выбор типа; эвристики запрещены |
| D-08 Сторонние стеки | Рекомендация «детект + управляемая очистка» | Утверждено: pre-flight только обнаруживает; очистка — отдельное действие с подтверждением и бэкапом; автоудаление запрещено |
| D-09 Flash-журналы | Объём не задан | RAM — подробно; Flash — только failover/emergency/apply-rollback/критические ошибки, кольцо 256 КБ + 1 ротация, rate limit |
| D-10 Backup | Состав не перечислен | Состав утверждён (подписки с токенами, серверы, профили, назначения, устройства, DNS/UDP, маршрутизация, версия схемы); Geo/логи/время исключены; без шифрования, права, предупреждение |
| D-11 Conntrack | «Диагностический показатель» как рекомендация | Утверждено: не критерий отказа, не влияет на failover, предупреждение > 80 %, sysctl не менять автоматически |
| D-12 Flowtable | «Проверить, при необходимости отключать» | Утверждено: не отключать глобально; сначала точечное исключение трафика; глобальное отключение — только с измерениями и отдельным согласованием |
| D-13 Подписки | Доопределение в узком месте | Утверждён полный порядок: приоритет подписок → сервер → профиль (кроме Restricted) → Pending reconnect; предпочтения не стираются |

**Важно (историческая запись; заменена более новым решением).** Рекомендация редакции 1 по Q-01 (отключить IPv6 для LAN-клиентов) не принята; на тот момент был утверждён вариант «не отключать подсистему, а обнаруживать глобальный IPv6 и безопасно ограничивать клиентский выход». **Актуально для v1 (ТЗ §5):** подсистема IPv6 сохраняется, но Guard, обнаружения глобального IPv6, предупреждения о нём, IPv6-фильтров и специальных правил, а также IPv6-тестов в v1 нет; настройки IPv6 OpenWrt не изменяются; риск IPv6 bypass принят пользователем. Документы №1 и №3 не должны содержать ни прежней рекомендации, ни требования о детекте/ограничении как действующих.

**Уточнение D-01 от 22.11.2026** (историческое; в v1 действует только в части фактов и границ, не требующих IPv6-механизма):

- у провайдера IPv6-доступа нет (подтверждено: `wan6 up=false`, нет адреса/префикса/default route, `ip -6 route get` → unreachable);
- IPv6-подсистема сохраняется только для внутренних нужд роутера;
- IPv6-туннелирование через Xray и IPv6 TProxy в v1 не реализуются;
- незаметный внешний IPv6-выход клиента — **нежелательный сценарий**, а не предотвращаемое в v1 свойство: прежняя редакция D-01 требовала его исключать, действующее ТЗ v1.0 §5 это требование **заменило**, и в v1 такой выход **не обнаруживается и не предотвращается** — риск IPv6 bypass принят (R3-01). Формулировка о недопустимости такого выхода относится к заделу v2 и действующим требованием v1 не является;
- внутренние IPv6-адреса роутера и клиентов не являются доказательством IPv6-доступа у провайдера;
- механизм ограничения внешнего IPv6 в v1 не выбирается и не реализуется: P-01 — **«закрыт — вне v1»** (ТЗ §5).

**Уточнение от 22.11.2026 (этап 2).** Xray на устройстве был остановлен владельцем **вручную** для восстановления прямого доступа в интернет — это штатное намеренное действие, а не отказ. Отсюда добавлено решение **D-14** (см. §7): состояние «VPN выключен пользователем» — отдельное штатное состояние; состояние VPN определяется по совокупности шести признаков. Формулировки о «неизвестной причине остановки/аварии» из документов №0–№8 удалены или исправлены; подтверждённым остаётся только недостаток механизма состояния (A-07, S1-03/S1-04).

Прежнее утверждение документов «IPv6 работает, есть IPv6 default route» **опровергнуто обследованием** (документ №8 §1.4, §2). Класс дефекта B-08 сохраняется как архитектурный (IPv6 вне политики), но активной утечки сегодня нет — есть латентный риск S1-01.

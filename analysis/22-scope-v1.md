# Документ №22. Объём v1: обязательное, облегчённое, после измерений, отложенное

Дата: 22.11.2026
Основание: ТЗ v1.0 §1, §18.10; решения №1–82; матрица №17.
Назначение: однозначно ответить «что входит в первую версию», «что делаем в упрощённом виде», «что нельзя включать до измерений» и «что не делаем сейчас». Классификация не меняет утверждённые решения — она определяет порядок и глубину реализации.

Классы: **v1** — обязательно; **lite** — облегчённая реализация с явным ограничением; **meas** — только после измерений/тестового окна; **defer** — отложено (кандидат v2); **out** — не входит в v1 принципиально.

---

## 1. Обязательное для v1

| Блок | Состав | Требования |
|---|---|---|
| Демон и владение | один Go-демон, procd, единый источник истины; Policy Manager (nft/fwmark/ip rule/route), DNS Manager, Xray Manager, Storage, Journal | REQ-004, 007–009 |
| API и безопасность | ubus/rpcd без сетевого порта, ACL + повторная авторизация, идентичность вызывающего, идемпотентность, оптимистическая блокировка | REQ-006, 014, 103, 111 |
| Конфигурация | JSON, атомарная запись, schema version и миграции, last-good, safe mode | REQ-100 |
| Состояния | D-14 (шесть признаков), `DISABLED_BY_USER`, `PROXY_FALLBACK_DIRECT`, `WAN_DOWN`, `EMERGENCY_DIRECT`, `MAINTENANCE`, `DEGRADED/*` | REQ-037–039 |
| Staged apply | фазы, `xray -test`, preflight outbound, trial, commit/rollback, восстановление после ребута | REQ-013, 104 |
| Подписки и серверы | одна активная подписка, устойчивые ID, приоритеты, профили независимы, Restricted | REQ-020–027 |
| Failover | 2 fail / 3 × 5 мин, ручной выбор немедленно, WAN отдельно от сервера, preferred ≠ active, авто-переключение серверов вкл / подписок выкл | REQ-030–036 |
| DNS | единый владелец, Domestic/Remote цепочки, Go DoH client, bootstrap, fallback с предупреждением, перехват 53 | REQ-040–045 |
| UDP | три режима, Quick Block (UDP-трактовка, OQ-06), Always DIRECT обходит, нет подтверждённой UDP-поддержки → селекторы off | REQ-050–055 |
| Устройства | MAC-идентичность, офлайн, Always DIRECT, переименование, группы (без routing rules), временный DIRECT overlay, tombstone 90/30 | REQ-060–065, 067, 068 |
| Blocklists | подсистема в Routing: источники, категории, дедупликация с происхождением, валидация, diff, staged apply, авто/ручной rollback, whitelist, системные исключения, история, статистика DNS-уровня, панель, аварийное отключение | REQ-070–083, 086, 087 |
| Диагностика | эффективная политика и причина, журналы, экспорт, внешние проверки с throttling | REQ-090, 091, 094, 095, 110 |
| Аудит и Undo | аудит настроек с источником и маскированием; Undo для безопасных изменений; критический auto-rollback | REQ-096, 097 |
| Надёжность | RAM/CPU/conntrack мониторинг без аварийных действий, Maintenance Mode, восстановление намерения | REQ-101, 102, 105 |
| Backup | авто перед критическими изменениями, ручной, лимит копий, без шифрования + предупреждение, проверка целостности | REQ-106, 107 |
| Self-update | preflight, backup, проверка после установки, rollback (в границах R3-05) | REQ-108, 109 |
| UI | семь вкладок, постоянный статус, один Quick Block, Saved/Applied/Pending, audit trail, без внешних уведомлений | REQ-099, 120–122 |
| Приоритеты | формальная модель №18, Dry Run с кодами конфликтов | REQ-022 |

**Принцип v1:** всё перечисленное реализуется **без** IPv6-политики, без ролей, без внешних интеграций и без обещаний, которые нельзя измерить.

## 2. Облегчённая реализация (lite)

| Функция | Что делаем | Что **не** делаем | Почему | Требование |
|---|---|---|---|---|
| Блокировка клиентского DoH/DoT | перехват 53, блок 853, известные DoH-эндпоинты | не блокируем произвольный DoH поверх 443, не анализируем TLS | технически невозможно надёжно | REQ-047 |
| Массовое управление устройствами | Dry Run, перенос в группу, назначение профиля, снятие | нет произвольных «массовых правок всего» | риск необратимых изменений | REQ-066 |
| False positives / анализ | отчёт по причине блокировки, добавление в whitelist, история правок | не объявляем домен «безопасным» автоматически | решение №66 | REQ-082 |
| Индивидуальные Blocklists по устройствам | набор категорий по устройству/группе с предупреждением о точности | без гарантии точной привязки DNS-запроса | кеш/DoH/DoT | REQ-085 |
| Статистика трафика | при достоверных измерениях; подробный сбор отключаемый | не показываем «скорость» при сомнительных данных | решения №67–68 | REQ-092 |
| Undo | только безопасные изменения, с проверкой зависимостей | не «отменяем» сетевые операции задним числом | риск | REQ-097 |
| Аномалии | пороговые предупреждения с объяснением | без автоматической блокировки/смены маршрутизации | решение №71 | REQ-098 |
| UDP Controlled | список портов/диапазонов, валидация | нет «умного» определения приложений | не требуется | REQ-050 |

## 3. Требует измерений (meas) — до измерений не включать

| Функция / параметр | Что неизвестно | Тест | Поведение до измерения |
|---|---|---|---|
| IPv4-таблица, fwmark, nft-priorities | занятость значений, порядок с fw4 | preflight + W-02 | значения предлагаются, не назначаются |
| Offload и per-device политика | обходит ли flowtable правила и счётчики | W-02 | политика проектируется без глобального отключения offload |
| 30 с / 8 с / ≤3 / 2 fail | нагрузка на CPU/RAM, ложные отказы | W-03 | утверждённые значения как стартовые |
| Trial-окно, время старта Xray, бюджет отката | длительности | W-04 | консервативные значения в конфиге |
| Ручное переключение «без разрыва» | реальный разрыв | W-05 | цель «без разрыва», иначе предупреждение |
| Кольцевой журнал | объём, ротация, сохранность | W-07 | 256 КБ + 1 |
| Backup | размер, состав, restore | W-08 | ≤ 1 МБ ориентир |
| Throughput/MTU | реальные числа | W-09 | без обещаний скорости |
| DNS reload без restart | работает ли reload | W-10 | reload, restart — крайняя мера |
| Идентичность rpcd/ACL | фактическое поведение | W-11 | контракт, без заявлений о безопасности |
| Blocklists: объём, RAM, время применения | лимиты | W-12 | консервативные лимиты, предупреждения |
| Интервалы обновления UI | отзывчивость vs нагрузка | W-13 | 2–5 / 5 / 5–10 / 30–60 с |
| Точность привязки DNS↔устройство | возможна ли вообще | W-14 | индивидуальные наборы — lite с предупреждением |
| L3-блокировки Blocklists (nft-наборы) | RAM ядра, время | W-12 | **не включаются**, статистика сети отсутствует |

Правило: ни один параметр из этой таблицы не выдаётся за подтверждённый; все они помечены [Т] в №10–№20.

## 4. Отложено (defer) — кандидаты v2

| Возможность | Почему отложено | Что нужно для возврата |
|---|---|---|
| **IPv6 Guard и обнаружение глобального IPv6** (P-01, S2-16) | ТЗ §5 прямо исключает из v1; риск принят (R3-01) | согласование механизма + тест с имитацией префикса + решение по DIRECT-устройствам |
| IPv6 VPN / TProxy / NAT66 | ТЗ §5 | отдельная волна требований |
| FakeDNS | решение №44 | отдельное решение + совместимость с Xray |
| L3-блокировки списков (nft-наборы) | не измерено (C3-10) | W-12 и бюджет RAM |
| Ролевая модель доступа | ТЗ §14: в v1 не нужна | требования к ролям |
| Уведомления Telegram/push/system popup | решение №71 | отдельное решение + канал доставки |
| Цифровая подпись пакетов/provenance | ТЗ §14 | инфраструктура подписи |
| Geo-базы как часть backup | ТЗ §14 | размер/лицензия; сейчас исключены |
| Автоматическое объединение MAC | запрещено (решение №52) | не планируется |
| Автоматическая очистка списков ради памяти | запрещено (решение №66) | не планируется |
| «Умное» определение приложений для UDP | не требуется | — |

## 5. Не входит в v1 принципиально (out)

1. Любая IPv6-политика, IPv6-фильтры, IPv6-тесты (ТЗ §5).
2. Сетевой порт демона, HTTP API, доступ из WAN.
3. Изменение системных UCI-зон `network`/`firewall`.
4. Запись в UCI из LuCI.
5. Гарантия блокировки DoH поверх 443.
6. Гарантия точной привязки DNS-запроса к устройству при DoH/DoT/кеше.
7. Обещания скорости/задержек без измерений.
8. Автоматическое «лечение» сети (очистка conntrack, смена sysctl, убийство служб).

## 6. Что увидит пользователь в MVP-сценарии

1. Установил пакет → Overview показывает `DISABLED_BY_USER` (VPN не включён сам).
2. Импортировал подписку → серверы с устойчивыми ID, профили провайдера помечены Restricted.
3. Включил VPN → `STARTING` → проверка трафика → `ACTIVE`; при сбое — `DEGRADED` с причиной.
4. Выключил → `DISABLED_BY_USER`, не ошибка; после ребута VPN не включается.
5. Добавил внешний список в Routing → увидел diff, аномалии, применил, при проблеме откатил.
6. Устройство «телевизор» → Always DIRECT с предупреждением; внешние списки к нему не применяются (OQ-09).
7. Диагностика объясняет: домен, источник, уровень (DNS/L3), правило, устройство.
8. Экспортировал backup → предупреждение о секретах; экспортировал диагностику → секреты замаскированы.

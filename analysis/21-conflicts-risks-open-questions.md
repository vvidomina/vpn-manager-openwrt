# Документ №21. Противоречия, риски и открытые вопросы

Дата: 22.11.2026
Основание: ТЗ v1.0 §2 (правила работы с решениями), §17 (зоны риска), §18.9, §21; волна 2 — разделы §3–§15 (реестр №16, где номера — идентификаторы строк, см. №16 §4).
Статус: документ **останавливает** работу в точках, где требуется решение пользователя. Агент не выбирает вариант самостоятельно.

Обозначения: **C3-xx** — противоречие/неоднозначность; **R3-xx** — риск; **OQ-xx** — открытый вопрос пользователю; **N-x** — требование, не встроенное полностью (перечень — №15 §5).

## 1. Противоречия и неоднозначности

| № | Где | В чём противоречие | Оценка | Как закрыто / что нужно |
|---|---|---|---|---|
| **C3-01** | ТЗ §5 ↔ D-01 (№5) и №10 §6, №14 S2-16/P-01 | D-01 (прежняя редакция, заменён ТЗ §5) обязывал **обнаруживать** глобальный IPv6 и **безопасно ограничивать** клиентский выход; ТЗ §5 прямо запрещает в v1 IPv6 Guard, обнаружение глобального IPv6, IPv6-фильтры и IPv6-правила | Не ошибка, а **более новое решение**: ТЗ v1.0 (волна №1–82) сужает v1 и принимает риск | ТЗ §5 имеет приоритет. P-01 **закрыт как «вне v1»**, S2-16 → «отложено», §6 №10/№11 помечены, `vpnmanager.ipv6` выведен из API v1. Замена D-01 зафиксирована как следствие более нового решения; **повторного подтверждения риска IPv6 bypass не требуется** (он уже принят ТЗ §5) |
| **C3-02** | ТЗ §5 ↔ ТЗ §16 | §5: «не проводить IPv6-тестирование в v1»; §16: последовательность тестов начинается с **W-01**, который и есть IPv6-измерение | Внутреннее противоречие самого ТЗ. **Решено в пользу запрета:** §5 — явный запрет, §16 — лишь предварительная последовательность | **W-01 запрещён в v1** (не «отложен до разрешения»). Расхождение с §16 зафиксировано как внутренний дефект ТЗ и передаётся владельцу как информация, **не как запрос на запуск**. OQ-01 закрыт |
| **C3-03** | ТЗ §17 ↔ ТЗ §10/§11 | §17 требует «отдельно определить», распространяется ли обход Always DIRECT на **внешние Blocklists**; §10 говорит «обходит все пользовательские правила проекта» | **Не разрешено ТЗ**: §17 прямо резервирует этот вопрос за пользователем | Модель №18 показывает порядок P1/P6 как **вариант (а), не утверждённый**. До ответа на **OQ-09** ни один документ не должен утверждать, что внешние списки к Always DIRECT не применяются |
| **C3-04** | ТЗ §9 (Quick Block) ↔ название и «аварийность» | Раздел называется «UDP и Quick Block»; не сказано, блокирует ли Quick Block только UDP или весь клиентский трафик | Неоднозначность формулировки | v1 реализует UDP-трактовку (по расположению в §9), UI не обещает блокировку TCP → **OQ-06** |
| **C3-05** | ТЗ §7 («PROXY временно DIRECT») ↔ ТЗ §13 («PROXY не должен незаметно уходить в DIRECT») и прежний принцип B-07 | Требование §7 проверено дословно и **существует**; противоречия с §13 нет, пока переход видим (баннер + событие). Но границы режима в ТЗ не заданы | Не противоречие, а **неполная спецификация** | Поведение сохранено как утверждённое (№20 §2.1); длительность, применимость к текущим соединениям и возможность отключить fallback — **открытый OQ-13**, значения не установлены |

| **C3-07** | ТЗ §6 («Restricted: запрещено … переключение») ↔ D-13 («Restricted не блокирует переключение подписки») | Неясно, что именно запрещено переключать: профиль или подписку/сервер | Неоднозначность | Трактовка: запрещено переключение **профиля** и любое изменение provider-профиля; переключение сервера/подписки разрешено. → **OQ-10** |

| **C3-09** | ТЗ §3 («не фиксировать лимиты до измерений») ↔ №13 §6 и S2-13 (512/16/64/256) | Числа уже присутствуют в документах | Не конфликт: они помечены [П]/[Т] | Числа остаются проектными ориентирами, не требованиями; в API — настраиваемые, с проверкой по RAM (REQ-002) |

| **C3-12** | ТЗ §14 (backup без шифрования, содержит токены) ↔ §14 (диагностический экспорт маскирует секреты) | Разные артефакты с разными правилами | Не конфликт, но легко перепутать | Зафиксировано: backup — с секретами и предупреждением; диагностика — всегда маскируется (R3-04) |
| **C3-13** | ТЗ §4 («нельзя доверять имени пользователя от браузера») ↔ фактическое поведение rpcd/ubus | Механизм не проверен на прошивке | Требует теста | Контракт описан (№12 §9); реализация [Т]; **OQ-11** — допустим ли `ubus call` от непривилегированного процесса как критерий |
| **C3-14** | ТЗ §8 (Remote DNS через VPN) ↔ ТЗ §5 (в v1 нет IPv6) | DNS-ответ AAAA может вернуть IPv6-адрес, который клиент попробует использовать | Следствие принятого риска | AAAA не фильтруется (скрытая смена поведения), риск R3-01 покрывает сценарий. Обязательного IPv6-предупреждения в UI v1 **нет** (REQ-011): сценарий фиксируется в документации проекта, отдельное постоянное предупреждение об IPv6 в UI v1 не создаётся |

## 3. Соответствие таксономий статуса (ТЗ §13 ↔ D-14)

| Ярлык UI (ТЗ §13) | Внутренние состояния |
|---|---|
| normal | `ACTIVE` |
| connecting | `STARTING`, `SWITCHING`, `APPLYING` |
| partial failure | `DEGRADED/*`, `PROXY_FALLBACK_DIRECT` |
| critical error | `EMERGENCY_DIRECT`, `DEGRADED/ENGINE_DOWN` без восстановления, `GUARD_*` (вне v1) |
| disabled by user | `DISABLED_BY_USER` |
| maintenance | `MAINTENANCE` |

Правило: **внутренняя модель — единственный источник**; UI-ярлыки вычисляются из неё, обратное преобразование не допускается.

| **OQ-12** | Поведение профилей с Geo-зависимостями после restore без Geo | (а) `Invalid` + предупреждение; (б) автоматически без Geo-правил | **(а)** — без тихой смены поведения | Меняет маршрутизацию пользователя |

**Правило остановки:** ни один из открытых OQ (кроме закрытого OQ-01) не решается агентом; до ответа соответствующие требования помечены [О] и не блокируют только те работы, где они не участвуют (см. №22).

## 5. Что блокирует реализацию сейчас

| Блокер | Что именно | Кто снимает |
|---|---|---|
| Нет разрешения на кодирование | ТЗ §1, §21: сначала независимое ревью | владелец |
| OQ-09, OQ-05, OQ-06, OQ-04, OQ-13 | влияют на модель приоритетов, UDP/Quick Block и режим PROXY_FALLBACK_DIRECT | владелец |
| OQ-11, R3-12 | безопасность API нельзя считать доказанной | тест + владелец |
| W-02, W-10, W-12 | параметры offload/DNS/Blocklists | тестовое окно |

Остальные параметры (таймауты, лимиты, интервалы) — **не блокеры**: они помечены [Т] и заменяются измеренными значениями без изменения утверждённой логики.

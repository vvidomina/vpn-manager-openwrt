Дата: 22.11.2026
Основание: ТЗ v1.0 §16 (этапы и последовательность), §19; документы №9 (W-02…W-09; W-01 запрещён в v1 и в план не входит), №14 (W-10 предложение), №17 (критерии), №21 (OQ).

## 1. Условия допуска к любому окну (gate)

Окно не начинается, пока не выполнено **всё**:

1. Утверждён письменный план именно этого окна: цель, команды, ожидаемые результаты, критерий остановки.
2. Есть снимок «до»: `nft list ruleset`, `ip rule`, `ip route`, `uci export`, `ubus list`, состояние служб, `df -h`, свободная RAM.
3. Есть проверенный откат для каждого шага, выполнимый без сети (если сеть пострадает).
4. Подтверждено, что кратковременная деградация доступа допустима; определено максимальное время перерыва.
5. Есть доступ к устройству не только по SSH через проверяемый канал (альтернатива: локальный доступ/консоль), иначе риск «запертой двери».
6. Все секреты в выводе маскируются тем же фильтром, что в `stage1/collect.sh`; логи окна не попадают в Git.
7. Явно указано, какие файлы/правила будут созданы и как удалены.
8. Ни один шаг не меняет `network`/`firewall` UCI (ТЗ §4, §5); если шаг это требует — он не выполняется, а выносится на согласование.

**Немедленная остановка окна:** рост числа ошибок dnsmasq; потеря default route дольше объявленного перерыва; трафик в мёртвый порт; непредусмотренное изменение сетевых настроек, включая IPv6 (v1 их не меняет и не измеряет); падение демона без восстановления; заполнение overlay.

## 2. Уровни тестирования

| Уровень | Где | Что проверяется | Сеть |
|---|---|---|---|
| Unit | локально | модель приоритетов (10 примеров №18 §3.2), валидаторы, парсеры списков, схемы, миграции, расчёт состояния по признакам | нет |
| Integration | локально/эмуляция | API↔модули, транзакция apply/rollback с фейковыми адаптерами, журнал, аудит, Dry Run | нет |
| Emulation (этап 2) | Docker/OpenWrt-эмуляция | ubus/rpcd, ACL, dnsmasq reload, nft-синтаксис, поведение при сбоях | изолированная |
| Device (этап 4) | AX3000T | W-02…W-14 (W-01 запрещён) | реальная |
| Acceptance | устройство + UI | сценарии §6 | реальная |

Роутер **не** используется как рабочая станция разработки (ТЗ §16).

## 3. Последовательность окон (ТЗ §16 + предложения)

Последовательность ТЗ §16: **W-01**, W-02, W-04, W-05, W-06, W-10, затем W-03, W-07, W-08, W-09. **W-01 из неё исключён** — запрещён ТЗ §5; окно v1 начинается с W-02.
Предлагаемые дополнительные окна (требуют согласования): **W-11** (идентичность/ACL), **W-12** (Blocklists), **W-13** (интервалы UI), **W-14** (точность привязки DNS↔устройство).

> **W-01 — запрещён в v1 (C3-02, OQ-01 закрыт).** ТЗ §5 дословно запрещает IPv6-тестирование в v1; предварительная последовательность §16, где W-01 стоит первым, этому противоречит, и действует запрет. W-01 — **не «ожидает разрешения»**, а исключён из v1 целиком (включая read-only часть). Окно v1 начинается с W-02. Риск IPv6 bypass уже принят пользователем (ТЗ §5) и повторно не подтверждается.

## 4. Карточки тестов

### W-01. Клиентский IPv6-выход — **ЗАПРЕЩЁН в v1 (не выполняется)**

> Карточка сохранена только как задел v2. В v1 не выполняется ни целиком, ни частично; никаких IPv6-команд, замеров, имитации префикса и изменения настроек IPv6.

| Поле | Значение |
|---|---|
| Что предполагалось выяснить | фактическое поведение IPv6 у клиента (диагностика, не политика) |
| Метод | **не приводится**: в v1 запрещены IPv6-команды, замеры и имитация префикса |
| Влияние | в v1 не выполняется |
| Перерыв | нет (окно не открывается) |
| Критерий | **отсутствует**: в v1 нет критериев выполнения W-01 |
| Откат | не требуется |
| Статус | **запрещён в v1** (ТЗ §5); не выполняется ни в каком окне, включая read-only часть и имитацию префикса; задел v2 — отдельный план тестов |

### W-02. Offload A/B (T-12)

| Поле | Значение |
|---|---|
| Цель | проверить, обходит ли flowtable per-device политику, BLOCK, UDP и счётчики |
| Метод | A/B: offload вкл/выкл; одинаковые сценарии DIRECT/PROXY/BLOCK/UDP; счётчики nft; throughput |
| Влияние | возможна деградация/рост CPU в окне; правила проекта временные |
| Перерыв | до 30 мин при переключении offload |
| Критерий | политика корректна при offload **либо** доказана необходимость точечного исключения; глобальное отключение не выполнено |
| Откат | вернуть настройки offload; снять временные правила; сверить ruleset со снимком |
| Риск | R3-07 |

### W-03. Мониторинг 30/8/3/2 (T-02)

| Поле | Значение |
|---|---|
| Цель | измерить CPU/RSS, ложные отказы, различение WAN/сервер, независимость проб |
| Метод | 3 параллельные пробы, цикл 30 с, timeout 8 с; имитация отказа WAN и отказа сервера |
| Влияние | нагрузка на CPU/канал; возможны ложные переключения в пределах окна |
| Перерыв | возможен краткий DIRECT при ошибочном переключении |
| Критерий | нет массового «все серверы down» при отказе WAN; 2 отказа основаны на независимых пробах |
| Откат | выключить мониторинг/вернуть конфиг; снять временные правила |

### W-04. Trial-окно, старт Xray, бюджет отката (T-06)

| Поле | Значение |
|---|---|
| Цель | измерить `xray -test`, время старта, listeners-ready, длительность trial, полный откат |
| Метод | серия apply с искусственными сбоями на каждой фазе; замер каждого этапа |
| Влияние | краткие разрывы; возможен выход в DIRECT между фазами |
| Перерыв | несколько окон по 10–20 с; суммарно до 15 мин |
| Критерий | нет трафика в мёртвый порт; откат возвращает last-good; длительности записаны |
| Откат | last-good + проверка трафика; при неудаче — emergency |
| Риск | появление «молчаливого DIRECT» — фиксируется как дефект |

### W-05. Ручное переключение и автовозврат (T-03)

## 6. Функциональные сценарии приёмки (без отдельного окна, этап 2–3)

| № | Сценарий | Ожидание |
|---|---|---|
| 1 | Первый старт, `intent=disabled` | `DISABLED_BY_USER`, VPN не включается, ошибок нет |
| 2 | Включение | `STARTING → ACTIVE` только после traffic proof |
| 3 | Ручное выключение | `STOPPING → DISABLED_BY_USER`, событие `disabled_by_user`, нет `DEGRADED` |
| 4 | `kill -9` Xray | правила сняты/не подняты, `DEGRADED/ENGINE_DOWN`, backoff, нет трафика в мёртвый порт |
| 5 | `kill -9` демона | политика сохраняется, procd перезапускает, состояние пересчитывается |
| 6 | Ребут при `intent=disabled` | VPN не включается |
| 7 | WAN down | `WAN_DOWN`, сервер не считается виновным, переключений нет |
| 8 | Все серверы недоступны, подписки off | `PROXY_FALLBACK_DIRECT` + постоянный баннер (границы режима — OQ-13) |
| 9 | Apply с невалидным конфигом | отказ до применения, last-good активен |
| 10 | Сбой в фазе APPLY | откат, проверка трафика, событие |
| 11 | Restricted-импорт | provider-профиль неизменяем, попытка правки → `VM_ERR_FORBIDDEN` |
| 12 | Blocklists: пустой/битый ответ | версия не создана/отклонена, активная не меняется |
| 13 | Blocklists: массовое удаление | `needs_confirmation`, без подтверждения не применяется |
| 14 | Blocklists: сбой после применения | авто-rollback, прежняя версия активна |
| 15 | Whitelist + пользовательский BLOCK | BLOCK сохраняется (P4 > P5) |
| 16 | Quick Block вкл/выкл | конфигурация побитово совпадает; Always DIRECT не затронут |
| 17 | Временный DIRECT, таймер истекает | прежний режим восстановлен, аудит записан |
| 18 | Параллельные изменения | второй запрос → `VM_ERR_BUSY` с `retry_after` |
| 19 | Устаревшая ревизия | `VM_ERR_CONFLICT`, данные не перезаписаны |
| 20 | Вызов без права | `VM_ERR_FORBIDDEN`, действие не выполнено |
| 21 | Restore несовместимой схемы | отказ с причиной, текущая конфигурация не тронута |
| 22 | Maintenance Mode | операции ограничены, политика сохранена, выход проверяет компоненты |
| 23 | Экспорт диагностики | секреты замаскированы, автоотправки нет |
| 24 | Dry Run и apply | одинаковый вердикт, Dry Run без побочных эффектов |

## 7. Формат протокола окна

Для каждого пункта: дата/время, версия прошивки и пакета, снимок «до», команды, вывод (с маскированием), наблюдения, критерий выполнен/не выполнен, откат выполнен, остаточные изменения, статус **пройдено / не пройдено / требует дополнительного теста**.

Запрещено: считать тест пройденным без записанного вывода; скрывать частичный успех; оставлять временные правила после окна.
